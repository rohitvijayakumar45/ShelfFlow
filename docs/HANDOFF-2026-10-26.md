## What was built this session (all in this commit)

1. **Model lineage** (`vision/training.py`, `tools/trainer.py`): a new run inherits the dataset frames and weights
   of the model in use, so it always knows every product trained before, even if their recordings are deleted.
   `POST /train` takes `parent` ("" = fresh). Train page shows "Builds on the model in use, which knows … Adds …".
   **Stop using** button (`POST /runs/{id}/deactivate`) lets you delete the model in use and start from scratch.
   Epochs: free number input (1–300). Training stops early on its own (patience ≈ epochs/3, ≥ 10); Stop keeps the best.
2. **Unknown check** (`vision/verify.py`): every YOLO detection is compared (DINOv2 cosine similarity) with reference
   crops of the product YOLO named, cut from that model's own training frames; too dissimilar → UNKNOWN.
   References are built automatically at the end of each training (`run/best-refs.npz`) and copied to
   `models/trained/active-refs.npz` on "Use this model" (built on the spot for older runs). Per-product threshold =
   5th percentile of the product's own validation similarity, clamped to [0.55, 0.75]. Used in the live view
   (`tools/detector_preview.py`), Test live (`tools/trainer.py`) and the shop (`vision/run.py`, averaged per track
   via `TrackCheck`). No references file → no check (old behaviour). Measured on the sanitizer-only model:
   own frames kept 47/50; old-camera Vicks 51/59 and Sunscreen 58/59 rejected.
3. **Earlier-system import** (`tools/import_pilot_training.py`): turns `data/shelf-pilot` (16 Oct hand-labelled
   frames of sanitizer/vicks/sunscreen + 25 Oct empty-tray frames) into Train-page recordings. The user later
   deleted those imported recordings and retrained everything from their own clips; the tool stays for reuse.
4. **Full shop workflow, part 1** (tested, NOT yet switched on):
   - **Strict auto-add** (`backend/config.py` `AUTO_ADD`, `backend/service.py` `timely_weight_source`): in hardware
     mode a camera event may update the cart without staff review when it cites exactly one shelf WEIGHT event
     that the laptop received during the camera window (stands in for the shelf's second-accurate clock), AND every
     existing fusion check passes (one owner via bracelet marker, hand-product-trajectory chain, weight matches a
     unit, vision agrees with weight, stock, single-use sensor evidence, two-shopper ambiguity → review).
     Off by default; needs `AUTO_ADD=true` and `WEIGHTS_ENABLED=true` in `data/integration/runtime.env` + backend restart.
     Tests: `backend/tests/test_auto_add.py`.
   - **Bracelet bands as identity** (`vision/hands.py` `split_bands`, `band_evidence`; wired in `vision/run.py`):
     YOLO classes `band-stripe` / `band-circle` are removed from the product list and become bracelet markers
     **200 (Stripes)** / **201 (Circles)**; the area around a band (3× its box, `band_hand_reach` in vision-config)
     acts as that wrist's hand. Existing marker → bracelet → session mapping then names the customer.
     Tests: `vision/tests/test_bands.py`.
   - **Sensor health**: the controller reports `ok=false` forever once its queue overflowed since boot (historical
     count, 67 at the end). Vision now treats the sensor as healthy unless that count grows during a pickup or
     there are fault flags (`SENSOR_QUEUE_LOST_EVENTS`). A controller reset (RST button, not a flash) clears it.
   - **Check-in** (`POST /staff/check-in/preview`, `POST /staff/check-in`; staff app Shoppers & checkout →
     Check-in & bracelets): scan the customer's entry QR → tap the bracelet on a shelf RFID reader → "Assign and
     start visit". Consumes the QR once, refuses unregistered / busy / pattern-less bracelets, one bracelet per visit.
   - **Bracelet register** form with pattern (Stripes/Circles) and "Use latest tap"; table shows pattern + wearer.
     The old dispenser/manual assignment moved into a collapsed "Bracelet dispenser (simulated gate)" panel.
   - **Train page**: "Bracelet with stripes" / "Bracelet with circles" in "What are you recording?" (classes
     band-stripe / band-circle; never charged).
   - **Staff exit backend** (`POST /staff/exit`, `GET /staff/visits/{id}`, `service.staff_exit`): one payment key per
     visit (`exit-<session>`), so repeats return the same bill; blocked while pickup/return events are pending.
     Customer cart now includes the bracelet's markers.
